## 修复范围

针对 Windows 实机截图中的超时、HTTP 200 正文错误和 OKX 盘口时间错误进行修复。已有四项增强、未知订单阻塞、持久化熔断、最后深度复核及实盘验证锁继续保留。本次没有使用真实账户 Key，也没有发送真实订单。没有发布云环境或合并 main；源码与 ZIP 交付到已授权的独立分支。

- **公共校时**：无 Key 的 OKX 实时轮询与全市场筛选也会先通过统一调度器读取公共服务器时间。缓存、优先级及额度继续受管理；不增加 Binance 时间请求。拒绝无效缓存、时钟回拨、超过 2 秒的同步往返和超过 30 秒的本机时差，提示同步系统时钟。盘口的默认 5 秒最大时效与未来 1 秒容忍未放宽。
- **错误分类**：分清等待响应头超时、正文超时、连接或正文中断、15 MB 超限、非法 JSON。HTTP 200 仅说明响应头成功，不能掩盖正文故障。显示安全的阶段、HTTP 状态、耗时、字节数和错误码，不输出请求 URL、私人响应、签名或密钥。所有交易提交异常仍为未知，不自动重发。
- **错误来源**：轮询错误标明 binance 或 okx；失败保留最后有效数据，并标记失败，不能授权新交易。
- **Windows 入口**：`4-start-proxy-7897-windows.cmd` 为用户已确认的本机 HTTP 代理 127.0.0.1:7897 设置本次进程环境，再调用原启动入口；不修改系统代理，不切换地区。
- **独立诊断**：`3-diagnose-windows.cmd` 调用固定的官方公开 time、rules、ETH 盘口 GET，报告响应与时钟质量。先停服务再运行，以免叠加公共额度。任一失败或非 200 后停止该交易所检查；不读 data/Key、不用私人接口、不启动服务、不下单、不关闭 TLS。时钟不可信时不把盘口时效判为可靠。

## Windows 更新与使用

1. 原服务窗口按 Ctrl+C 正常停止，若询问终止批处理则输入 Y；完整备份旧 `data`。
2. 新包全部解压到单独的新目录，双击 `1-install-windows.cmd` 安装锁定依赖。
3. 如需保留已有设置和安全记录，把完整旧 `data` 复制到新目录；不要删除锁、未知订单或熔断记录绕过问题，不同时运行两份。
4. 保持代理软件运行。本机 HTTP 代理为 127.0.0.1:7897 时，双击 `4-start-proxy-7897-windows.cmd`；浏览器打开 `http://localhost:8888/`。
5. 若要诊断，先正常停止服务，再双击 `3-diagnose-windows.cmd`，按回车采用当前 7897 代理；报告仅反映诊断，不修改服务配置。具体错误截图可用于继续定位，无需分享 Key。
