# 提示词逐项对照与本轮修正

本项目按用户粘贴的十项“双交易所现货套利与库存平衡工具”要求准备。支持 Binance Global 与 OKX Global 两个适配器，不含三角套利、期货、链上交换、提现、自动补单或自动成交查询。A、B 可交换方向，不能将任意交易所名称视为已支持。

| 要求 | 实现位置与状态 |
| --- | --- |
| Node.js 20+、本地 Web、8888、持久化、加密 | Node.js >=20.18；原生前端；server/store；配置、批次、限速及风险阻塞持久化；AES-256-GCM；本地单进程锁。 |
| 查询／交易 Key 隔离、多查询 Key 同账户轮换 | exchanges/store；公共请求无私人 Key；查询凭返回 UID 验证；交易 Key 禁止查询，其归属由用户声明，不能伪称已远端验证权限。 |

## 本轮修正

1. **最大持仓复核**：Binance 存在 MAX_POSITION 时使用账户级开放订单查询（权重80），拒绝同基础币其他交易对的开放买单；未知交易对／畸形数量拒绝放行。没有该过滤器时仍使用当前交易对查询（权重6）。
2. **账户单笔资产限制**：每笔通过查询 Key 获取 myFilters（权重40），复核 MAX_ASSET。基础币按订单数量，报价币按数量乘限价；上下文缺失、过期、账户／交易对不匹配或不支持的资产过滤器均拒绝放行。
3. **完整复核预留**：普通路径最坏约97权重、MAX_POSITION路径约171权重；预留100／175。配置预算至少120／195才允许实盘，另外保留一次20权重的后台规则获取空间。官方窗口、观测到的其他IP用量及队列仍可能进一步延迟；这不是交易延迟保证。
4. **验收统计**：所有请求／失败分类取本次窗口差，旧盘口、旧周期与历史批次不能充当本次成功证据；记录开始、结束、服务端口、完整轮转与实盘状态，检测进程重启及目标改变。

## 保留的规格边界

- 按用户要求采用“仅提交”模式：不自动查询成交，不自动补单。收到订单号只代表受理；两腿申报数量相同不保证实际成交相同。
- 任意已受理、未知或不完整批次必须人工核对两腿和库存后才可继续。归档、重启均不清除风险。这是要求的保护行为，不应为了连续运行而移除。
- “完整盘口”是 REST 本次返回的全部档位：Binance前100档／OKX前400档。超出实际取得的深度拒绝计算，不假设无限深度。
- 备用金额仅在原金额的深度／利润／交易规则计算不通过后尝试；本轮没有新增资金不足自动降额或未要求的新策略。

## 外部验收阻塞

当前环境对 api.binance.com、www.okx.com 及 OKX 官方文档返回代理 CONNECT 403。Binance 适用 REST／过滤器／错误文档已从其官方 GitHub 重新取得并对照，哈希与项目快照一致。OKX 官方适用文档尚未完成核对，docs/verification.json 保持 okx=false，后端实盘锁保留。

需要在环境设置保存并发布所需域名访问，再实际复测并完成 OKX 文档、适配与契约测试，才能解除对应验证锁。不能只修改布尔标志视为接入完成。本次没有配置真实 Key、没有私人账户验收或真实资金订单。后续 Key 应由用户在本机界面输入，不能发在聊天中。

## 复现

在 /workspace/spot-arbitrage 执行：

```bash
npm ci --ignore-scripts
npm test
npm start
```

服务只监听127.0.0.1:8888。在另一个终端运行 `npm run soak`，观察正常服务至少65秒；`npm run soak -- --fixture` 使用独立临时实例及本地协议数据，不连接交易所。两者报告分别保存在 reports/soak-network.json 与 reports/soak-fixture.json，不能互相替代。

长期运行使用 README 中的用户 systemd 服务模板或平台进程管理。重启后实盘仍关闭、风险阻塞仍保留；应完整备份 data 目录并保护 master.key。分享源码包时必须排除 data、.env 和任何真实凭据。
