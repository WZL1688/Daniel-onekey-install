# Windows 本机安装与启动

不需要安装 Ubuntu。这是 Node.js 应用，不是双击 `package.json` 或 HTML 文件即可运行的程序。

1. 在 Windows 10/11 上，从 [Node.js 官网](https://nodejs.org/) 安装当前 **LTS Windows 版**；保留默认的 npm 和加入 PATH 选项。运行时要求 Node.js 20.18 或更新版本。
2. 将 ZIP **全部解压**到自己用户目录中的一个文件夹。不要在压缩包预览窗口内运行，也不要放到共享目录、公共下载目录或网盘同步目录。
3. 双击 **`1-install-windows.cmd`**。首次需要联网下载锁定版本的依赖；出现 `Installation finished` 后按任意键关闭。
4. 双击 **`2-start-windows.cmd`**，保持命令窗口开启。看到“现货套利工具已启动”后，在浏览器输入 **`http://127.0.0.1:8888`**。如果自行设置过 `PORT`，将地址中的 `8888` 换成服务日志显示的端口。
5. 关闭服务时，在启动窗口按 `Ctrl+C`。先正常停止服务，再关机或备份数据。不要同时启动两份。

两个 `.cmd` 文件使用带引号的项目路径并关闭延迟变量展开，允许路径包含空格、中文或 `!`；不要求管理员权限，不修改 PowerShell 执行策略，不开启实盘，不设置公网监听。安装使用 `npm ci --ignore-scripts --no-audit --no-fund`；失败时保留错误输出，不能通过关闭证书验证来绕过错误。

如果 Windows 提示找不到 Node，完成安装后关闭原命令窗口再重新双击。若提示端口被占用，先关闭已经启动的工具；若提示数据锁损坏或被占用，保留数据并检查其他实例，不要手动删锁文件、未知订单或熔断记录。

## 本机代理与行情诊断

浏览器能访问交易所，不代表 Node.js 会自动使用 Windows 的系统代理。本工具从启动进程的 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 读取代理配置；在另一个 CMD 里设置变量，不会改变已经运行的服务。

- 如果本机 HTTP 代理确实在 **127.0.0.1:7897**，先正常停止旧服务，再双击 **`4-start-proxy-7897-windows.cmd`**。它只为本次服务设置代理，不修改 Windows 设置，也不改变交易所访问资格。代理软件需要一直运行。浏览器打开 **`http://localhost:8888/`**。
- 其他代理地址或端口：在项目目录打开 CMD，按实际地址设置 `HTTP_PROXY`、`HTTPS_PROXY`，将 `NO_PROXY` 设置为 `localhost,127.0.0.1`，然后在同一窗口运行 `node src/server.js`。不要将 SOCKS 端口当作 HTTP 代理端口。
- 先正常停止工具服务，再双击 **`3-diagnose-windows.cmd`** 运行独立公开接口诊断，避免两个进程叠加公共 API 用量。按回车使用本机 `http://127.0.0.1:7897`，也可按提示输入实际 HTTP 代理地址或 `direct`。它不启动服务、不读取应用 data 或 Key、不查询私人账户、不下单；只检测固定的官方公共时间、规则和 ETH 盘口接口。报告不输出代理地址、密码或响应正文。
- 出现 HTTP 451 表示服务端限制访问；请核实交易所官方支持范围或联系官方客服。出现 HTTP 200 也需要完整读取和验证正文，不能仅凭状态码认定行情有效。诊断遇到非 200 或网络失败后会停止该交易所的后续探测。
- 新版公共 OKX 行情通过统一调度器主动校时，不要求配置 Key；盘口依然按原有时效、未来时间容忍和时钟偏差上限检查。若提示本机与交易所时间偏差过大，请在 Windows“设置 → 时间和语言 → 日期和时间”核实自动设置时间并同步时钟。更改时区显示本身不修正系统时间戳。

更新时先正常停服并完整备份旧目录中的 `data`。将新版解压到**单独的新目录**，安装依赖后，把完整 `data` 复制到新版目录，再启动新版；不要同时运行新旧两份。不要删除旧凭据、未知订单、限速或熔断记录来清除错误。Windows 启动截图已经证明管理页可运行，但网络及真实账户、实盘仍需分别验证。

## 数据与平台边界

- 默认数据在项目的 `data` 目录，包含加密后的凭据和本机主密钥；不要上传或发给别人。备份时正常停止服务，再完整备份整个目录。
- Windows 的 `chmod(0600/0700)` 不能替代 NTFS 的账户访问控制；请将工具放在自己的用户目录，确认其他本机用户无权访问。程序不自动修改 ACL。
- 各平台都先将完整状态写入同目录临时文件、同步文件，再原子替换状态。Linux/macOS 还会同步目录；Node.js 在 Windows 上不支持目录 `fsync`，因此原生 Windows 显式跳过目录同步，不忽略文件写入、同步或重命名错误。Windows 在突然断电时对最近一次目录变更的持久性保证较弱；正常停止和完整备份仍然必要。
- 同一个数据目录只允许一个进程，自动交易在每次重启后均保持关闭。风险熔断与未知订单继续保留。
- 本轮可执行的实际环境为 Linux；已覆盖 Windows 分支的模拟测试，**尚未在原生 Windows 上完成运行验收**。不要将平台兼容修改视为真实交易验证；交易所接入、账户权限和实盘边界仍以主 README 为准。

## 可选：运行自动化测试

在解压文件夹的地址栏输入 `cmd`，回车后执行 `npm test`。测试入口会明确列出测试文件，不依赖 Windows 命令行展开通配符。原生 Windows 的文件权限与目录同步行为不同于 POSIX，测试也会按平台区分这些保证。
