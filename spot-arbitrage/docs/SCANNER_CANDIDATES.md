# 中小币候选池

候选池用于从两所共同的现货市场挑选值得继续观察的交易对。它通过排除名单、指定候选列表、扣费净收益和真实返回盘口深度筛选，没有接入流通市值数据；币价低、成交额低或盘口浅都不能据此标为小市值。

## 使用

1. 进入“设置”，编辑“扫描排除基础币”。默认排除 `BTC, ETH, SOL`，可以自行增加或删除。排除只影响候选扫描，不会删除当前关注、库存、历史批次或熔断。
2. “扫描候选交易对”留空时，从两所共同且可交易、报价币匹配的市场选择；也可填已经核对过的 `基础币/报价币` 列表以缩小范围。候选名单不是关注名单，不能填入只在一所上线的交易对来绕过共同市场要求。
3. 确认原有手续费、固定缓冲、再平衡估计和利润门槛。流动性设置仍可约束每所最大所内价差、两侧限价内最小有效深度、两所盘口接收时差；执行数量继续按共同步长取整并重算深度和利润。
4. 保存后回到“实时机会”，在下方“中小币候选池”点击“开始一轮筛选”。新一轮从快照列表开头扫描，显示总数、已处理、失败数、当前交易对及起止时间。完成表示本轮已处理结束，不表示所有候选盈利或可成交。
5. 有效且通过门槛的结果优先展示，再按保守净利润排序。表中列出试算金额、深度及限价净利润、收益率和限价内深度。各方向、默认金额和备用金额的原因可展开查看。
6. 仅将少量合适的候选点击“加入关注”，后台随后重新采样。此按钮只更新关注列表，不提交订单、不启用实盘。已有关注、达到 30 对或实盘/批次忙时按钮禁用。加入关注属于配置变化，会使旧筛选预览失效，当前轮停止时可按提示重新开始。

每次只深度筛选一个交易对，间隔至少 10 秒，并让位于实时行情和最终复核。100 个候选至少需要约 17 分钟，网络、退避和配额还会延长时间；它不是同时高频扫描全部币种的工具。关注交易对也公平轮转，数量增加会延长轮询周期，应保留精选名单。

## 结果状态

- **通过 · 待复核**：只代表当次新鲜盘口按设置计算通过。开启资金配额但未取得有效余额时，仍显示“资金未核对”；不能直接授权交易。
- **不满足**：深度、费用、利润或其他原有过滤没有通过。备用金额逐一试算，不降低门槛。
- **已过期**：只展示历史计算。原有盘口时效未扩大；旧正利润不以当前可获利机会显示。
- **最近失败**：保留最后成功值和最近失败原因，但历史值失效。失败计入扫描进度，并继续处理后续币种，避免一个失败币拖住整轮。

停止筛选会关闭自动筛选配置并阻止在途旧结果回写，实时关注行情继续运行。配置变化或开启实盘会停止本轮；停止实盘后是否开始新的自动轮次由原自动筛选配置决定。服务重启保留历史结果和进度，中断的手动轮次不会悄悄续跑。页面刷新只读取本机缓存，不触发交易所请求。

## 资产与交易边界

同名基础币和相同报价币只构成候选，不足以证明两所是同一个资产。需核对项目、合约、网络及是否为拆分/包装代币；本功能没有新增自动资产身份认证、提现、转账、跨链或永续策略。

原有最终盘口复核、余额/精度/最小订单、资金配额和亏损熔断继续生效；受理、未知或不完整批次仍阻塞新单，不能自动重发或补单。OKX 后端实盘验证锁和真实账户、成交验收边界保留。候选筛选不保证出现机会，也不保证利润能够实际兑现。

## 配置字段

| 字段 | 含义 |
| --- | --- |
| `scanExcludeAssets` | 排除的基础币列表，默认 BTC/ETH/SOL，空列表表示不额外排除。 |
| `scanPairs` | 限定候选交易对列表，默认空列表表示全部共同市场。 |
| `scanQuote` | 扫描报价币，沿用原设置。 |
| `scannerAuto` | 自动筛选开关，沿用原设置；实盘开启时不会扫描。 |

两个名单各最多 300 项且不可重复。旧数据补充缺失字段，保留 Key、运行数据、未知订单、额度、冷却和熔断。可通过受会话/CSRF 保护的 `/api/scan` 开始新轮、`/api/scan/stop` 停止；接口不会调用下单。
