# 真实报价复核与盈利证据（v1.8.0）

“参考价差”“真实报价复核通过”和“实际净盈利”是三个不同阶段。工具不能保证每笔盈利或未来70%的成功率；两链交易不是原子成交，链上确认等待会改变价格、费用和可用库存。

## 使用流程

1. 在“行情首页 → 同币机会”开启自动发现与扫描。默认寻找已收录的BNB／Solana双链山寨币，排除已识别的稳定币及BTC／ETH／BNB／SOL表示；保留原有活跃度、时差、多池价格与异常隔离检查。
2. 对参考价差达标的候选，展开详情核实发行方、两链地址、1:1数量关系、精度和交易池，保存映射确认。名称相同、目录ID相同或池价格一致都不足以证明资产等价。
3. 在“设置与钱包”分别提供两链公开钱包地址。只读地址即可用于真实报价复核；不需要导入私钥。配置并解锁自己的OKX API凭据，两链RPC与报价API须能连接。
4. 点击条目中的“真实只读报价复核”，或在套利看板开启“自动只读复核”。该开关只逐个复核已核验且符合扫描条件的候选，每60秒最多一次；不会切换实盘模式、开启交易、请求签名、发送授权或广播交易。
5. 在套利看板查看真实报价结果、保守净价差、压力检查和未通过原因。模式仍为演示时，也可独立取得真实报价；虚拟资金演练结果不进入真实报价结果或实盘成功率。过期、钱包／风险配置变更、资产版本变更或行情异常时，不沿用通过状态。

## 检查的含义与边界

双侧库存模式按配置的1–10U金额买入报价，再以买入最小到账换算另一链卖出数量，检查卖出最低到账、现有库存、完整费用估算、租金、滑点、价格冲击、Gas储备与原风险限制。保守净价差已经扣除双腿报价费用和最小到账滑点。

在此基础上，真实只读复核另设固定压力场景：卖出最低收入再降低0.5%，报价费用再增加25%。压力后的净价差仍须达到用户利润门槛，整个计划还须至少保留3秒有效期。这个场景是筛选缓冲，不是市场变化上限，也不是成功概率模型。

只读复核不执行链上成交模拟，因此不会显示“已验证可卖出”。真实聚合报价、路由校验和费用估算通过，仍可能遇到代币限制、转账税、抢跑、流动性变化、滑点保护失败或网络延迟。若需要授权，真正执行仍需单独完成授权与前置模拟，缺失时会停止；复核开关不会代为授权。

报价有效期以真实API请求开始时间起算，而不是网络返回后重新给满时长。实际执行在买入前、签名前和广播前再次核对计划；BUY确认后根据实际到账重新报价。跨链模式在跨链前和卖出前也再次核算总净收益；买入已发生但后续条件不通过时暂停待人工核对，保留状态、库存预占与哈希，不重播或自动补卖。

稳定币仍按1美元面值、原生币费用按配置参考价折算；这是估值假设，不代表稳定币永远锚定或费用美元估值已实时验证。库存模式的双腿现金价差没有包含未来补库的费用和风险。

## “七成”按什么统计

用户选定口径：买卖两边均有确认回执、实际收支与费用完整一致，扣费后净盈利，才算成功。跨链模式还要求中间跨链腿确认；库存模式与跨链模式分别统计。

统计只读取本机实盘套利档案，最近200笔按开始时间选择。模拟记录、桥接再平衡和只读复核不作为真实盈利样本。失败、待确认、待人工核对、缺费用或无法核验的记录都保留在分母，不仅挑成功记录。档案哈希及回执结构会核对，但本功能没有独立联网重验链上真实性；外部钱包交易及后来删除的本机档案不在统计内。

看板同时显示样本数、观察到的盈利比例和95% Wilson统计区间下限。至少100笔且区间下限达到70%时，只显示“历史证据达到目标”。不足、未达标、没有真实样本时明确显示未验证，不编造“70%预测成功率”。跨资产汇总不能当作单一代币的胜率；市场变化、相关成交和滚动窗口也会限制统计解释。

这些数据不承诺下一笔或未来成功率。无需为验证软件而充值或发起真实交易；本版软件测试全部使用本地模拟和固定响应，没有使用用户钱包、真实API账户或资金验收。
