# 同币机会与库存模式

ChainPair 1.6 在“行情首页”增加“同币机会”子视图，保留原来的套利看板、Meme 雷达和五个主标签页。它将多币发现、行情初筛、同币映射核验、指定金额双边报价及执行分开处理。新增库存模式不要求每笔把买入代币跨到另一条链，但需要两侧提前备好资金和代币。

## 1. 安装与入口

安装 [Node.js 24 LTS](https://nodejs.org/) 或更新版本，解压源码包，在项目目录运行：

```sh
npm ci
npm start
```

Windows 也可双击 `start.cmd`，macOS／Linux 可运行 `./start.sh`。保留终端，使用它显示的完整本机地址，例如 `http://127.0.0.1:50240/`；实际端口由本次启动分配。只输入 `http://127.0.0.1/` 或使用上次启动的旧端口，可能无法连接。

默认交易为演示，首次启动自动进行只读发现与扫描；用户手动停止扫描后会保存选择，重启不会重新打开。演示交易不会签名或广播；机会扫描独立读取真实公开行情，因此“交易为演示”不表示所有功能离线。真实发现不可用时，页面会显示原因，不生成模拟市场结果。

## 2. 自动发现的范围

目录发现优先读取 CoinGecko 同一 coin ID 下具备两链地址的项目，同时独立读取 CoinPaprika 的 BNB／Solana 合约目录，按完整统一资产ID相交，剔除一个ID在同链有多个地址或地址被多个ID复用的歧义。每平台请求分别占用预算，并缓存实际采集时间。发行方地址快照补充已核实来源的项目，当前为 BabyDoge。Wormhole32组旧快照保留观察，默认其中稳定币和BTC／ETH／BNB／SOL类资产不会发起池请求。

CoinGecko和CoinPaprika各最多保存200组，Wormhole和发行方来源各最多100组，手工最多100组，注册总量最多400组。优先导入范围内候选，每轮按最多30组轮换请求准确地址对应的池；这不是全链合约枚举。CoinPaprika返回ID与地址，名称符号由ID派生用于显示，不参与配对。两链平台标识为bnb-binance-coin及sol-solana，而不是EVM链编号。
CoinGecko coin ID 只是元数据关联：不能证明两条链上的表示始终 1:1、可兑换、可卖出或安全。项目可能是原生资产、第三方包装币、旧版本合约或其他表示。名称、符号、图标相同不能认作同币；LP、可重基或有换算比例的资产不能套用当前 1:1 模式。

本功能覆盖所取目录、官方包装资产映射和可选手工清单，不枚举全链所有代币或所有池。DexScreener 官方接口按已知地址查询，不提供本工具可依赖的全链代币分页目录。未被目录收录的新币不会因为名字相同而自动配对。池报价若只把目标币列为计价币，不能把另一个资产的 `priceUsd` 当作目标币价格。

目录使用公开免 Key 接口尝试读取；第三方可能要求凭据、改变访问规则、限流或临时不可用。接口要求凭据时，在“数据源连接（CoinGecko Key 可选）”填写自己的 Demo Key 和保险库密码。Key本机加密、不回显；保存不表示验证通过，也不会解锁原本锁定的交易钱包。没有Key时也会尝试官方映射备用源。新增扫描不需要钱包私钥或 AVE Key，不能据此承诺第三方 API 永久免费。AVE Meme 雷达仍使用自己的 Key、缓存和预算，与本扫描分开控制。

## 3. 建立并核验清单

1. 在“行情首页”打开“同币机会”，程序自动载入双链候选并扫描。若曾经停止过，点击“开启自动发现与扫描”；需要一次性刷新可点“立即发现并扫描”。无需先手工添加币。
2. 查看发现数量、已扫描数量、两侧有效池数量、来源状态与下一次重试时间。自动显示参考价差不要求填写交易用精度或批准映射；准备交易时再核对两链合约、发行方、池和精度。
3. 在相应条目展开“核对并确认同币映射”，填写两链 decimals、交易池和映射依据，勾选 1:1 确认，再点击“保存此映射确认”。依据可记录发行方说明、原资产链和地址、核验时间等，不能填成“名字相同”。
4. 只有已核验且启用的项目才具有库存执行资格。新目录候选不会自动核验，也不会自动修改全局套利地址。
5. 地址、精度或池变更后重新核验。目录发现的地址变化不能悄悄替换已经批准的执行地址，会撤销原确认并保留原因。核验新地址后可移除旧条目、按已确认地址重新手工添加；不要把变更警告当作程序已接受新地址。

“已核验”代表使用者确认了当前映射与参数，不代表程序或第三方为代币安全背书。目录和池服务也不提供完整的貔貅、税费、冻结权限或持仓风险证明；原有安全待核验边界仍适用。

## 4. 从参考价差到可执行报价

扫描结果首先展示两链参考价格、池、流动性、采集时间、买卖方向和价差。参考毛差价按当前套利金额估算，费用未知时不会显示为可执行净利润。界面刷新和翻页只读取本机状态。

点击指定项目的“复核双边报价与库存”后，程序才按全局设置的 1–10U 金额、两侧准确资产和当前钱包获取两笔兑换报价，并检查：

- 资产映射、精度、池、主网、钱包、授权与允许的交易格式。
- 低价侧可用稳定币、高价侧已有目标币，以及双方 Gas 储备。
- 最低到账、滑点、价格冲击、费用、租金、利润门槛和报价有效期。
- 执行次数、累计套利金额和其他未完成交易占用的库存。

报价不能核验、费用不完整、库存不足或超过限额时保留不执行原因。初筛价差和上一次报价都不能保证稍后仍能成交。执行前会重新报价和检查；即使报价复核通过，两条链的交易仍不原子。

默认扫描设置：

| 设置 | 默认值 |
| --- | --- |
| 自动扫描 | 首次默认开启；重启延续用户选择，交易仍默认关闭 |
| 轮询间隔 | 60 秒，允许范围至少 30 秒 |
| 每轮扫描项目数 | 30，轮换清单 |
| 最低参考池流动性 | 20,000 USD |
| 最低参考价差 | 50 bps，即 0.5% |
| 稳定币、BTC／ETH／BNB／SOL表示 | 默认排除，池请求前生效 |
| 每侧24小时成交量 | 10,000 USD |
| 每侧1小时成交量 | 100 USD |
| 每侧1小时索引交易数 | 3笔 |
| 两侧采样最大时差 | 30秒 |
| 异常价差上限 | 3,000 bps，即30%，超出只列待核对 |
| 参考池数据有效期 | 固定 120 秒 |
| 本机滚动 24 小时请求上限 | 5,000 次 |

参考池数据的有效期按本机采集时间计算。DexScreener 未提供可用的源价格更新时间时保持未知，不把采集时间冒充为链上成交时间。两侧需来自同一轮并保持新鲜，不能把两次相隔很久的价格拼成机会。

所有新扫描源共用至少 1 秒的请求间隔及每分钟最多 30 次的控制，有效目录通常缓存6小时；网络失败采用60秒起、最长15分钟的指数退避，账户权限失败等待15分钟或更新凭证，成功目录为空则15分钟后重试。所有失败计数，429仍遵守服务端冷却。目录失败不会清掉错误或中止可用备用候选的池扫描；池源权限失败会停止池扫描。手动刷新不能绕过限制，重启不能清除已用预算。这些是本机请求数控制，实际可用额度与费用以数据提供方为准。

## 5. 库存模式怎样交易

在“设置与钱包”选择“库存模式”，与演示／实盘开关分别设置。旧配置默认仍使用跨链模式。单一配置币对需核验当前两链映射；多币执行使用清单中各项目的核验参数和独立执行上下文，不通过频繁改写全局代币地址来切换交易。

库存流程固定为：

```text
检查双方资金、目标币库存及完整报价
→ 低价链买入
→ 等待买入回执确认
→ 按实际到账换算高价链卖量并再次检查库存
→ 卖出高价链已有代币
→ 复核两笔回执、现金流、库存变化及精度余数
```

例如在 BNB 买入 100 个 X，确认后可在 Solana 卖出事先持有的 100 个 X。新买入的 100 个仍在 BNB，Solana 侧库存减少，稳定币增加。两边只有 USDT／USDC、没有高价侧 X 时不能完成这种交易。若要两个方向都能执行，通常需要两侧都准备目标币、稳定币及原生 Gas 资金。

卖量来自买入实际回执，按两链 decimals 作整数向下换算；不能使用最初估算数量，也不能因另一侧库存较多就多卖。换算不足一个原始单位、超过链上整数范围或资产关系无法确认时停止。精度余数留在买入侧并单独归档，不伪造为另一侧已成交。

买入前预占高价侧库存，实际买入确认后再检查准确卖量。失败或结果不确定的占用保留，只有完成或人工核对后才释放，防止后续任务重复使用同一份库存。持续同方向执行会耗尽低价侧稳定币或高价侧代币；库存不足时跳过，等待反向机会或由使用者另行补库存。

库存模式不会自动调用同币桥接，也不会触发自动稳定币再平衡。手动跨链页仍可独立使用，需要使用者明确操作并通过原有费用、磨损和储备检查；它不应被当作单笔库存套利已经包含的免费补仓。

## 6. 开启自动执行

扫描开关只读取行情，核验项目只管理执行资格，二者都不等于开启交易。可先逐项获取报价并查看不执行原因，再明确开启已核验清单的自动执行。该操作使用当前演示／实盘模式和全局风控，不会把演示偷偷切成实盘，也不会批准新发现的币。

自动执行仅考虑已核验、已启用、数据新鲜的项目，逐项复核真实报价和库存。多个项目仍共用金额、执行次数、累计金额与费用规则，不能按项目各自重置限额。点击停止自动执行阻止新周期，已发送的链上交易不能由按钮撤销。

实盘继续使用现有钱包与 OKX 适配器。BNB ERC20 所需精确授权由使用者事先在外部钱包完成；程序不隐式发送 approve。当前只接受适配器已支持且可核验的 ABI、白名单程序、配置池和经典 SPL Token，Token-2022 不在支持范围。插件钱包仍逐笔弹窗确认，需保持页面打开；自动扫描和自动触发不能让插件变成无人值守签名器。

## 7. 收益、失败与归档

库存模式显示的是本轮现金流价差：

```text
高价侧卖出实际稳定币
－低价侧买入实际稳定币
－双方实际网络／协议费用
－实际租金
```

估算中的 `feeUsd` 已含适配器提供的预计租金时，不再重复扣减；实际记录分别保留费用和租金。美元估值仍使用稳定币面值及交易创建时配置的原生币参考价。

这不是库存已配平的闭环利润：两链代币和稳定币分布发生变化，未来补库、跨链、兑换、授权、充值等外部成本不一定包含在本轮回执中。档案应结合两侧库存变化、原始数量和精度余数阅读，不把补库存成本默认为零，也不承诺持续盈利。

买入未确认禁止卖出。买入后报价变化、库存不足、卖出失败、回执不一致或签名结果不明时暂停、保存已有证据并要求人工核对，不自动重播、补卖或切换为跨链。重启仍有未完成记录时继续保持人工核对状态。人工确认释放相应占用，不代表追回资产或补齐另一笔交易。

## 8. 来源与验收边界

发现和池客户端依据官方接口独立实现：

- [CoinGecko coins/list](https://docs.coingecko.com/demo/reference/coins-list)：使用 `include_platform=true` 获取 coin ID 与各平台合约地址。
- [CoinGecko 平台目录](https://docs.coingecko.com/demo/reference/asset-platforms-list)：核对平台 ID，不能将其与 EVM 或其他协议的链编号混用。
- [DexScreener API](https://docs.dexscreener.com/api/reference)：按准确链和已知 CA 查询池；批量请求最多 30 个地址，不是全链目录。
- [Hummingbot](https://github.com/hummingbot/hummingbot) 与 [Gateway](https://github.com/hummingbot/gateway)：参考双侧库存、费用与报价复核的工程思路，没有在本工具中安装或直接启动第三方交易服务，也不照搬可能优先卖出的成交顺序。

本功能没有导入外部安装器或交易机器人源码，不新增第三方钱包权限。目录、代币名称、接口错误及映射说明均作为数据处理，不能触发安装、读取秘密、签名或任意网络请求。

开发验收使用本地模拟响应、受控时钟、模拟钱包与交易回执；尚未使用真实 CoinGecko／DexScreener 账户或用户资金完成运行验收。真实 RPC、公开接口权限、实际路线、授权、流动性和资金仍需分别核对。具体测试结果见 [TEST-RESULTS.md](TEST-RESULTS.md)，不能将测试通过当作真实成交或盈利证明。


## 9. 重复启动与异常退出

同一数据目录只允许一个交易进程，重复启动会显示提示；正常退出自动释放运行锁。崩溃后确认原PID已退出时，下一次启动可恢复。若锁文件损坏或恢复标记残留，请先确认旧进程全部退出并备份数据，再移除该数据目录的 `runtime.lock`、`runtime.recovery.lock` 后重启；存在旧进程时不要删除锁。

真实公开行情及资金验收边界见最新验证记录；官方映射元数据已核对，不能据此声称完成实时价格或真钱交易验收。


## 10. 自动发现失败时

页面会保留失败来源、固定诊断分类、发现/扫描进度和真实的下一次目录重试时间。HTTP200的本机状态响应不等于外部源成功；没有有效池或价格会明确显示0或未知，不会报告已找到可执行收益。目录成功与交易池成功分别记录，空清单或后续轮询不会清除原错误。

内置官方映射只是带日期的原资产地址快照，不含价格、余额、精度猜测或交易批准。32组候选按原始链与原始合约关联；不是按同名币配对。包装资产仍有桥风险，可能没有当前流动性，来源与许可证见 [第三方数据说明](THIRD-PARTY-DATA.md)。

升级会修复v1.4失败请求占用6小时本地目录冷却的问题，保留已消耗请求数、滚动预算及服务端429退避。设置环境变量 `DUALARB_AUTO_SCAN=0` 可禁止本次启动自动扫描，适合离线演示或测试；页面仍可手动开启。AVE Meme雷达继续使用自己的开关，不受此设置改变。


## 11. v1.5.1 行情网络设置

网络设置位于同币机会页，不需要导入钱包。自动模式优先使用继承的 HTTP_PROXY／HTTPS_PROXY／NO_PROXY（兼容小写）；没有环境代理时，在 Windows 读取当前用户启用的手动代理。仅有 ALL_PROXY 或不支持的 SOCKS 配置会提示检查 HTTP／mixed 端口，不会悄悄改为直连。不会读取执行 PAC 或自动探测端口。也可以明确选择直连，或手工填写带实际端口的本机 HTTP 地址。

设置仅作用于 CoinGecko 目录、Wormhole 官方地址映射及 DexScreener 池行情，其他 RPC／OKX／AVE 连接未被此项代理设置修改。代理地址及环境凭据不会出现在公开状态或复制诊断里；用户自己保存的无密码本机代理地址用于编辑设置，保存在本机 SQLite。

只读连接检测使用固定的公开 WBNB、WSOL 地址和 CoinGecko 目录接口，分别显示响应与记录数、HTTP状态、固定错误分类和检测时间。WBNB与WSOL用于测试各链行情接口，不是同币组合或推荐交易资产。检测成功不代表其他代币有池、可卖出或能盈利。目录检测使用已解锁的自己的 Demo Key（如有），不会保存返回候选、核验映射或触发交易。

检测与扫描共用持久请求计数、每秒／每分钟／滚动日预算；一次检测最多三个公开请求、至少一分钟间隔。供应商429退避不能通过保存网络、刷新、重启或反复检测绕过。检测可能等待多路超时，请保留本机程序窗口。保存新连接会取消旧扫描和检测，清除旧连接诊断并等待新结果，缓存行情保留且仍受原有新鲜度限制。

TIMEOUT表示截止时间内未取得响应，不足以单独确定网络封锁、代理端口错误或服务故障。请按三路结果核对：两条链均失败先查本机HTTP代理与API网络；仅CoinGecko401／403则核对该服务凭据与权限。浏览器打开普通网页和npm安装成功都不能证明API可达。不要用关闭TLS校验来处理证书错误。


## 12. v1.6 山寨币筛选与来源边界

默认榜单仅展示范围内且双侧池通过流动性、成交量、笔数、同轮采样及新鲜度检查的项目；参考价差达标项优先，异常大价差不显示为绿色收益。未入榜原因、观察清单与范围排除数可单独查看。高级范围／活跃度参数会持久保存；改参数不清除请求账本或限流，也不会开启交易。

第三方目录共享ID仍不能证明两链表示1:1、可赎回或可卖出；手工核验数量关系的交易边界保持。数据源没有收录的跨链项目、只有同名的模仿币和未确认官方映射的新币不会被当作同币。池h1成交笔数／成交额是索引活动指标，不能证明无刷量或精确最后成交时间。池作为quote侧时使用baseUSD/priceNative换算，不能把base价格误当目标币价格；同池两个请求方向分别记录，冲突响应隔离。

CoinPaprika两平台缓存各自保留采集时间；一侧失败不丢掉另一侧有效缓存，超过6小时不能继续合并。重用缓存不会把目录更新伪装成实时网络成功。CoinPaprika429对其两个平台共同生效，CoinGecko限流独立，公开池仍受共享本机预算与各提供方冷却。保存可用代理后，已清除的网络失败来源可立即进入重试，服务端429不被解除。


## 13. v1.7 异常比较隔离

超出异常价差上限的比较保留原始参考价格和异常百分比供诊断，但不再估算毛差额或收益，不进入默认或参考候选榜单。即使页面仍收到旧版带数字的异常快照，也会独立隔离并阻止使用历史evaluation执行。禁用按钮使用明确灰色和原因提示。

后台对手动复核、授权验证、执行入口及每腿执行上下文检查已知隔离状态；扫描变异常后旧授权立即不能使用。买入确认后或异步卖出余额检查期间发现异常时，禁止SELL，暂停并将已有买入证据、尝试额度及库存占用保留为待核对，不重播或补卖。首次没有公开池行情时仍可对已核验项目请求独立适配器新报价，保持既有手动核验流程；已知异常不会因缺少下一次行情而清空。

本机opportunities.comparison-quarantine.v1保存范围内项目的隔离状态及首次异常的公开池快照；不含钱包地址、签名或私钥。仅新一轮双侧有效行情可释放隔离，单侧缺失、过期正常数据、手工确认映射、换代理或重启不能解除。释放后仍须新报价，不恢复旧授权。主动移除观察条目会清除其记录。

详情分别展示当前池与首次异常池地址、记录时间和固定DexScreener链接，历史区明确“历史，非当前报价”，不会把历史价格当作当前值。价格来源方法仅说明采集与计算路径，不认证源数据正确。针对用户AntFun异常，由于原池地址未保存，不能确认具体错池／索引／单位原因；不能仅凭差价巨大断言两个目录地址是不同项目。


## 14. 套利看板中的扫描机会

看板读取同一个机会扫描服务，不新建另一套价格、不自动获取交易报价。默认展示范围／活跃度／新鲜度／价差阈值通过的公开参考项，隔离项、过期项、无效方向、重复身份和无同轮标识的结果不会显示。可切换可执行报价组，要求映射批准、当前资产版本、当前执行模式、金额、完整费用／利润和有效期，还核对父执行上下文版本及风险指纹；钱包更换但仍能签名时，旧报价也会失效。实盘钱包锁定、断连、执行忙碌、配置更新或待核对暂停时不宣称旧报价可执行。

每8秒读取本机快照，过期检查每秒更新展示；2.5秒全局状态轮询不会重置筛选或增加扫描API调用。切页会中止／丢弃迟到结果，读取失败停止展示旧可执行项，部分目录故障会明确提示。看板刷新只重读本机结果，不冒充重新采集外部池行情。点击项目打开对应资产详情，保留核验／报价／执行为显式操作。原设置币对的行情和演示流程单独标注，避免混同公开扫描行情。

## 15. 同链多池价格核对

仅同一准确代币地址的合格活跃池参与表决：默认两两价格窗口最大偏离15%，不作相邻价格无限传递合并。选择唯一最大一致窗口里的实际池报价，优先其中流动性较高池；不会生成不存在的平均报价。多个最大窗口若没有共同中心池则隔离；若有共同中心，仅使用真实中心池。一个流动性很大的离群池不能压过两个价格一致的合格池。历史、指标不足、错误链、相同池地址重复行不计有效票，冲突重复记录隔离。

已核验池不会被替换；缺失时返回缺少行情，价格与多池共识矛盾时隔离。一条链曾有多池冲突，会在隔离记录单调保留需重新多池核对的要求，哪怕此前首次证据来自跨链异常；后续竞争池缺失／仅剩单池也不能自动释放。新鲜同轮有效价格及所需链的多池一致通过后，才解除隔离并要求重新报价。

priceConfidence与poolDiagnostics仅描述索引数据比较，不验证底层持币人独立、无刷量、合约税费或实际卖出；单池可观察但不冒称已交叉验证。根本资产单位关系与真实双边可成交性仍以核验、受限报价和回执为准。
