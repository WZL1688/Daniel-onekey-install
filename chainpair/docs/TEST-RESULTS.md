# 验证记录

版本：1.5.0。验证日期：2026-11-20。环境：Node.js v24.19.0 / Linux / Chromium。

## 自动测试

`npm test`：247 / 247 通过；`npm run check`：通过。

覆盖顺序交易、确认前置、实际数量传递、单边失败暂停、持久化档案、重启不重播、执行互斥、配置及钱包身份变化并发、累计费用/储备、磨损与60/40再平衡、RPC轮换和主网身份、支持的ABI与实际回执归属。

插件钱包新增测试覆盖：

- 插件不向服务端提供私钥；本机钱包加密、锁定和恢复仍可用。
- 请求归属当前页面、仅交付一次；相同结果可重传，不重复调用钱包发送交易。
- 用户取消、账户/网络切换、心跳过期、结果篡改、过期报价的停止与归档。
- EVM由插件广播一次，哈希返回立即记录，并核对真实RPC交易意图；本机不重复广播。
- Solana签名消息完全一致、Ed25519签名有效、原生币和代币模拟通过后，才由本机记录哈希并广播一次。
- 过期EVM结果仍可保存晚到哈希并要求核对；过期Solana签名不广播。
- 同时连接第二条链不会被第一条链的网络刷新阻塞；旧钱包的延迟余额和报价无法覆盖新状态。

## v1.2.0 执行边界与本地复盘

新增独立交易意图校验与参数快照：错误链、代币、精度、数量、收款人、过期/过长报价、未知费用及超出链上整数范围，均在广播前被阻止。每步实际数量绑定确认回执，参数变化中止后续步骤并保存原指纹。指纹用于配置一致性追溯，不是不可篡改存储或外部安全认证。

新增本地复盘与受保护的脱敏导出：按上海完成日期、演示/实盘分别统计；缺失或矛盾记录不计入已核实收益，同样本估算比较单独计数，未知收益不伪装为0。测试验证导出不包含秘密、地址、哈希、原始报价或备忘录中的外部指令。复盘及定时任务只写复盘记录，不调用签名、下单或配置更新。

修复跨链有利成交的利润计算，利润独立于非负磨损指标，估实差异使用同一净收益定义；验证大额跨链正常浮点误差不会误判为费用缺失，明显收支错误仍被拒绝。

`npm run test:review-ui`：通过。六组浏览器流程覆盖复核收益/同样本差异、对应日期与模式的JSON导出、空白时期未验证、过期响应/切页保护、模式隔离、390px布局、文字转义及无执行/配置/签名写请求，零页面/控制台错误。

没有引入外部研究模型、第三方代理安装器、Kelly自动仓位或夜间实盘策略发布。仍未进行真钱交易验收。

## v1.4.0 同币机会与双侧库存

新增 CoinGecko 同 coin ID 双链地址候选发现、DexScreener 精确 CA 批量池扫描、版本化人工映射确认与已核验清单自动执行。目录、池源、清单服务与执行协调器独立；名称和符号不能确定同币，目录关联不会自动获得交易资格。所有新请求保留超时、响应体限制、固定域名、无重定向、持久请求计数与退避。

新增库存模式只执行 BUY→确认→SELL，使用另一链已有库存，按买入实际到账换算不同精度，保存精度余数和两链库存变化。买前预占库存，卖前按最新余额和准确数量再次核验；单边失败保留预占并暂停。库存不足不进入买入，库存模式不会隐含跨链或自动再平衡。所有资产共享1–10U及累计额度；独立上下文不修改全局代币配置。

测试覆盖：来源地址冲突、跨链同名不配对、目录变化撤销确认、手工清单不依赖目录权限、同轮行情与120秒时效、未知费用不可执行、映射版本与模拟/实盘模式校验、迟到数据丢弃、父级互斥、实际实收换算、库存消耗与隔离、预占跨连接持久化、单边失败暂停、不重播、全局执行上限、显式自动执行的真实本机API完整流程（使用模拟行情与成交）。原已核验单币配置改变地址、精度、池或标识会撤销旧确认。

运行锁测试验证同一数据目录拒绝重复交易进程、正常释放与死亡PID恢复。库存现金流价差单独统计，未纳入闭环净收益；归档保留未回补库存与精度余数，统计及脱敏复盘不把未来补库存成本视为已结清。交易档案同时读取最新统计，避免刚成交后显示旧累计数据。

五组浏览器流程均通过：`test:ui`、`test:wallet-ui`、`test:review-ui`、`test:radar-ui`、`test:opportunities-ui`。新增页面验证映射确认→双边报价→手动提交、独立自动执行开关、身份改变撤销勾选、库存/闭环收益分列、XSS转义、分页、未保存输入保留、迟到响应、五标签与390px布局。

尝试读取 CoinGecko 目录、BNB 与 Solana 的 DexScreener 公开池接口，开发环境均返回网络不可达分类（DISCOVERY_NETWORK）；因此不能声称完成真实公开源联通验收。没有使用用户私钥、真实OKX凭据或真实资金。实际可用性仍取决于用户网络、API权限、RPC、库存、授权和受支持交易格式。


## v1.5.0 自动发现与扫描修复

修复已复现的空清单故障：目录失败不再被空扫描清除错误，也不再因为失败占用6小时本地冷却；一次扫描可以自动建立候选。下一次目录重试时间、来源错误、发现数、扫描进度和双侧有效池数均单独显示。本机HTTP200状态快照不再被页面当作外部行情成功，本机读取失败也不被旧页面状态覆盖。

首次启动只读自动扫描，之后延续用户的扫描选择；交易仍默认关闭。新增32组固定版本官方Wormhole原资产映射候选，并支持固定官方映射的受限数据读取及可选CoinGecko DemoKey。官方数据已核对来源并由严格对象语法解析器处理，禁止执行远端TypeScript；附日期、原始链/地址、出处及Apache许可。快照没有价格、钱包余额、目标精度猜测或批准状态。参考价差候选在交易核验前也能查看，但不进入自动交易清单。

新增测试覆盖：启动自动发现/双链扫描无人工条目、目录网络失败保留、指数重试与跨重启预算、旧版冷却迁移、官方网络备用源和随包候选、手工清单自动扩充、每源RetryAfter不饿死独立交易池读取、修改凭证不删除服务端限流、取消任务丢弃迟到数据且不追加请求、未核验候选不交易、严格解析器拒绝注入/表达式、请求头Key隔离、成功正文反射Key拦截、凭证加密/重启锁定/不解锁交易钱包。

六组页面流程通过：`test:ui`、`test:wallet-ui`、`test:review-ui`、`test:radar-ui`、`test:opportunities-ui`、`test:automatic-scanner-ui`。新增页面覆盖HTTP200失败快照、长期错误提示、恢复后的扫描进度、无需交易批准即可查看参考候选、Key输入及时清空、固定官方来源、XSS、分页、390px及无意外执行请求。

官方Wormhole映射原文件已实际取得并解析出32组双链候选。CoinGecko和DexScreener实时接口在本开发环境的联通尝试仍失败（DISCOVERY_NETWORK）；没有提供真实账户Key，没有完成实时价格、报价或真钱验收。测试和官方地址快照不能证明当前有流动性、机会或可实现收益。
