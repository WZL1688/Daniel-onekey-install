# 使用说明

## 1. 先运行演示

安装 Node.js 24 或更新版本，在项目目录运行 `npm ci`、`npm start`，或使用 `start.sh` / `start.cmd`。启动后会请求默认浏览器自动打开页面。如需手动打开，复制终端显示的完整本机地址，必须包含端口，例如 `http://127.0.0.1:50240/`。仅输入 `http://127.0.0.1/` 会访问默认端口，不能打开分配在其他端口上的程序。端口每次可能不同，收藏的旧地址可能失效。保留启动命令窗口。

默认“演示”使用本地模拟器；行情卡片、余额、报价及带 `demo-` 前缀的哈希都不来自链上。连接真实插件钱包后，演示余额仍是模拟数据，也不会发起真实交易签名。演示不需要导入任何真实私钥。首次安装依赖完成后，演示可在离线状态运行。

在行情首页可查看两链价格、流动性、数据时间、连接状态、套利方向和净收益估算。执行一笔演示套利后，在交易档案查看各状态、报价、回执和实际收益。自动模式会在条件满足时发起新交易，达到次数或累计额度后停止触发。

## 2. 五个标签页

| 标签 | 用途 |
| --- | --- |
| 行情首页 | 套利看板显示双链报价与执行状态；Meme 雷达观察 AVE 榜单；同币机会管理多币候选、映射核验、扫描、报价及库存执行 |
| 设置与钱包 | 设置链、RPC、代币、池、风控；连接插件或导入两链钱包、配置 OKX 凭据、解锁或锁定保险库 |
| 跨链 | 获取 BNB ⇄ Solana 稳定币报价，复核到账与磨损后执行；配置自动再平衡 |
| 交易档案 | 分页查看交易、参数快照、哈希与回执；人工核对异常记录；生成本地复盘和导出脱敏 JSON |
| 备忘录 | 保存本地文字，自动记录时间，分页查看或删除 |

普通页面时间以浏览器本地时区显示；归档时间保存为带时区的标准时间。本地复盘的日期边界固定为 `Asia/Shanghai`。备忘录、档案和复盘写入本机 SQLite，刷新或重启后仍可查看。

## 3. 配置链与钱包

### 链配置

每条链分别填写目标代币地址、decimals、稳定币地址与 decimals、交易池地址、多个 HTTP(S) RPC。BNB 使用合约地址，Solana 使用 mint 地址。默认稳定币是 BNB USDT 与 Solana USDC，它们是不同资产，按面值 1U 估值。

多 RPC 会轮换并在只读请求失败时尝试其他端点。每个端点都检查主网身份：BNB chain ID 56，Solana 主网 genesis hash。已签名的广播不会自动改用另一个 RPC 重发，避免结果不明时重复执行。

交易池用于展示行情，也用于校验实盘成交路线。当前采用严格池校验；OKX 路线必须提供可匹配的池地址，否则显示阻止原因。仅配置相同币名不能证明两链资产等价，应自行核实合约、发行方及桥接映射。

### 直接连接插件钱包

1. 在打开本机网页的同一个浏览器中安装、启用并解锁钱包插件。
2. 打开“设置与钱包”，点击上方“钱包管理”，或向下找到“插件钱包与本机密钥”。
3. 在 **BNB Chain 钱包**卡片点击“连接 MetaMask”或“连接 OKX Wallet”；在 **Solana 钱包**卡片点击“连接 Phantom”或“连接 OKX Wallet”。两条链可使用不同插件和账户。
4. 在插件弹窗允许连接。BNB 侧还会检查主网 56，必要时请求切换网络。页面显示公开地址和“插件已连接”后，账户连接完成。

本机网页使用 `http://127.0.0.1:实际端口/`；回环地址可供支持该浏览器的插件使用。若提示没有检测到插件，请确认插件装在当前浏览器、允许在该页面运行，解锁后刷新页面重连。连接按钮只申请公开账户，不要求把插件私钥导出给程序。

插件交易需要人在场：每笔链上交易会请求插件确认，页面顶部显示待处理步骤。保持本机服务和当前网页打开。连接权限不等于交易签名，连接成功本身不会发起套利。实盘仍需完成 RPC、代币/池、白名单、余额与费用检查，并配置、解锁本机加密的 OKX API 凭据。无人值守执行使用本机加密私钥模式。

刷新网页或重启程序后需再次点击连接；程序只保留插件公开地址和名称，不保存可自动恢复签名的会话。账户或 BNB 网络变化时会断开该连接并暂停新交易；关闭网页后心跳过期，程序不再把该插件视为可签名。首页“行情已连接”指行情数据源，钱包状态另行显示；演示模式中的余额一直是模拟值。

如果此前已经导入本机私钥或只读地址，连接插件会保留原本机钱包配置。点击该链卡片的“恢复本机钱包”可切回；恢复私钥钱包后，保险库若锁定仍需密码解锁。“锁定密钥”管理本机保险库；断开插件请使用“断开插件连接”。

### 两链本机钱包分别导入

- BNB 私钥：64 位十六进制，可带 `0x`。
- Solana 私钥：64 字节 Base58，或含 64 个字节的 JSON 数组。
- 只读：仅输入链对应的公开地址，可查看余额，不能交易。

私钥只需在本机页面输入。首次建立保险库时设置至少 10 个字符的密码；后续导入另一链私钥或 OKX 凭据使用相同密码。提交后页面清空敏感输入，接口只返回公开地址和锁定状态。请勿把私钥或密码发到聊天中。

私钥和 API 凭据用 scrypt 派生密钥、AES-256-GCM 加密保存。程序重启后锁定，输入密码即可继续使用已保存的钱包，不必重新导入私钥。只读地址没有签名能力。程序不能找回遗失的保险库密码。

### OKX 与白名单

在本机页面填写 OKX Web3 API Key、Secret Key、Passphrase；如账户需要，填写 Project ID。凭据与私钥使用同一本地加密保险库，不写入公开配置或浏览器持久存储。

实盘签名前要求审核过的 BNB 路由合约 / spender 白名单，以及 Solana 程序白名单。白名单初始为空，会阻止签名。应依据当前官方文档和具体路线核对后添加，不要把错误消息中出现的地址未经审核全部加入。

BNB ERC20 授权必须提前通过外部钱包完成。程序发现 allowance 不足时会给出 spender 与本笔原始数量，随后暂停；本程序不发送隐藏的 approve 交易。授权操作本身的费用不属于本程序已发送交易的回执，计算总体资金成本时需自行加入。实盘支持边界与 API 来源见 [LIVE-ADAPTER.md](LIVE-ADAPTER.md)。

## 4. 套利风控与顺序

套利单笔设置范围为 1–10U。金额限制只用于套利，不用于手动跨链或自动再平衡。

| 参数 | 含义 |
| --- | --- |
| 最低利润 | 全流程保守预计净收益门槛，美元计 |
| 最大滑点 | 报价允许的最低到账与预期到账差额，1 bps = 0.01% |
| 最大价格冲击 | 路线报告的价格冲击上限 |
| BNB Gas / SOL 网络费 | 一次流程累计原生币费用限制 |
| Gas 储备 | 扣除预计费用后仍须保留的 BNB / SOL |
| 执行次数与累计金额 | 本地档案中已预占的套利尝试额度，失败或不确定尝试也计入 |
| 报价有效期与轮询间隔 | 防止使用陈旧报价；实际成交前仍会重新报价和检查 |

在“设置与钱包”选择执行模式；旧配置默认为跨链模式。跨链模式固定为买入确认、实际买入代币跨链、目标链确认、按目标链实际到账数量卖出。买入和目标到账确认是后续动作的前置条件，卖量来自目标链归属明确的回执。

库存模式固定为低价链买入确认，再按实际买入量换算并卖出高价链已有库存，不在单笔中跨链。高价侧必须预先持有准确映射的目标币，低价侧必须有稳定币，两边均需原生币费用及储备；两边只有稳定币时不能执行。不同 decimals 用整数向下换算，余数单独归档。单一币对或多币清单都需核验 1:1 映射、合约、精度和池，不能按币名配对。

引擎还会根据配置和已确认回执，独立核对报价的源链、目标链、代币地址、精度、准确输入数量、最低到账及有效期；实盘同时核对发送方和收款钱包。初始计划不一致时禁止买入，后续真实到账的报价不一致时暂停核对。报价费用或价格冲击未知时不会按零处理。

买入后市场可能变化，跨链模式还需要等待跨链。最初利润门槛无法保证最终收益。后续步骤仍检查报价时效、滑点、价格冲击、费用与 Gas 储备；库存模式还会在实收数量确定后重新检查另一侧可用库存。任何无法核实的步骤都会暂停并保存已有记录。

风控阈值是程序停止或阻止执行的条件，不是实际损失上限保证。两种模式都不是两链原子交易，确认等待、价格变化、转账税及流动性变化仍可能导致亏损。库存模式的现金流价差也不代表已完成库存配平，未来补库、外部授权等成本需另外核算。

点击暂停会停止新周期；已发送的链上交易无法由本机按钮撤销，在途流程仍按状态机处理与归档。关闭程序也不会撤销已广播交易。

## 5. 手动跨链与自动再平衡

### 手动跨链

在跨链页选择方向，输入稳定币金额，先获取报价。检查预计到账、网络费、美元磨损、磨损率、Gas 储备和过期时间，再执行。方向对应所配置的两链稳定币，默认 BNB USDT ⇄ Solana USDC。

程序不设置跨链单次上限或每日上限；资金余额、路线最小额、磨损限制与保留 Gas 仍必须通过。报价过期后重新获取，不能重复使用已提交的报价。报价来源不支持所选路线时不会绕过或伪造报价。

美元磨损包括输入稳定币面值与保守预计到账之差，以及本钱包承担的网络费用估值。跨链方在代币到账中扣除的成本已反映在到账差额中，避免重复相加。实际结果还会记录本钱包实际支付的网络费与租金。

### 自动再平衡

自动再平衡仅在跨链执行模式下生效，需要同时启用再平衡配置与自动运行。库存模式跳过自动再平衡，不会为了补仓悄悄跨链；手动跨链页仍可独立使用。触发阈值固定为一侧可用稳定币 **低于 5U**，目标固定为不足侧约 **60%**、来源侧约 **40%**。执行金额根据预期稳定币到账折损求解 60/40；磨损风控仍使用保守最低到账及网络费用。实际比例会受报价变化与实际到账影响。

为避免反复跨链，还需要：

1. 资金总量足以让来源侧保留至少 5U。无磨损时总量至少约 12.5U，有磨损时需更多。
2. 满足美元磨损、磨损率、Gas 费用与储备限制。
3. 上次再平衡后经过冷却时间，默认 30 分钟。
4. 完成后需两侧重新达到触发线以上，才重新具备触发资格。

例如 BNB 有 3U、Solana 有 27U 时，BNB 是不足侧。忽略费用时会从 Solana 转入约 15U，得到 BNB 18U / Solana 12U。若两侧总共只有 8U，程序会阻止把另一侧推到 5U 以下的再平衡。

## 6. 复核、失败与重启

每一步在请求签名或广播前保存提交意图。本机广播前保存已签名交易的确定哈希；BNB 插件自行广播时，在收到插件返回的哈希后立即保存，再通过 RPC 核验实际交易。发送、确认、到账、卖出与最终复核都保留状态事件。完成后保存输入与到账原始数量、Gas、租金、实际滑点、实际利润及相对估算的差异。

每笔新交易还保存 `policySnapshot` 与 `policyFingerprint`。它们记录创建交易时的执行模式、资产映射、风控、确认数、白名单和估值参数，供核对当时执行依据；不包含 RPC 地址、API 凭据或钱包秘密。执行期间相关参数与快照不一致会阻止后续提交。历史记录若缺少这些字段，页面保留缺失，不自动推测历史配置。指纹不是第三方安全审计或盈利证明。

美元结果使用稳定币 1 美元面值和配置中的原生币美元参考价。更改参考价不会把它变成独立的实时价格源。需要精确复算时使用档案中的原始费用、数量和交易时汇率。代币转账税、退款、部分成交或无法核验的净变化会引发人工核对。

插件取消、断线、签名超时或结果无法核实，也会中止后续步骤并进入人工核对。请求不会自动重播。BNB 插件可能已广播但较晚返回哈希，程序会将迟到哈希补记并要求核对；过期的 Solana 签名不会由本机程序广播。

出现 `NEEDS_REVIEW` 时：

1. 先取消插件中仍打开的待确认交易弹窗，再在交易档案打开记录，核对最后状态、源链哈希、目标链哈希、链上成功 / 失败状态及钱包实际余额。
2. 确认是否仍持有买入代币、是否有待到账桥接资产，以及是否存在可继续处理的资金。
3. 在页面填写人工核对说明并确认，再决定是否重新开启自动运行。

人工确认只解除该记录的阻止状态，不会重试、追回资产、自动补卖或自动补偿。库存模式失败或结果不明时保留库存占用，完成或人工核对后才释放；应先核对已买入、已卖出和实际可用的代币，不能把释放占用当作资产恢复。重启发现未完成交易时也执行同样规则，程序不会重播提交意图。

### 本地复盘与脱敏导出

1. 打开“交易档案”，找到“本地复盘”面板。
2. 选择日期并生成或刷新报告。报告按上海时区划分日期，演示与实盘数据分开；模式与当前设置一致。
3. 查看已完成与已复核笔数、净收益、网络和协议费用、租金及估实差异。收益归入完成日期，不按发起日期提前确认。
4. 点击“导出脱敏 JSON”，下载供人工或独立分析工具查看的统计报告。

缺失费用、租金或收支无法对应的完成记录会列为“不完整”，不计入已复核收益。没有可验证记录时，收益显示未验证。估实差异只比较同时具有有效估算与实际结果的配对样本，需结合比较笔数阅读。“当前待核对”统计该模式目前全部未解决记录，不仅是所选日期的记录。

报告只覆盖本工具已归档交易。外部钱包的手动授权、充值等额外费用未必在其中，需另行核算；美元结果仍采用稳定币面值和交易时原生币参考价。报告是成交后的复盘资料，不应直接当作历史时点的交易信号或回测输入。

程序运行期间，在每日上海时间 00:05 后保存前一天的报告；启动时到达相同时间条件，也会补生成缺失的前一日报告。报告按日期和模式更新保存，不会修改交易配置、调整限额、自动发布策略或发起交易。本程序没有接入外部研究模型，也不会自动上传复盘数据。

导出仅保留日期、模式、计数、数值汇总和程序生成的固定检查提示，排除钱包地址、哈希、原始报价、RPC、备忘录、原始失败文字和密钥。原始交易证据仍保存在本机交易档案中。复盘建议需要人工检查，不会自动应用。后续开发可采用 [安全开发说明](SAFE-DEVELOPMENT.md) 中的约束。

## 7. 数据保存与本机访问

默认数据都位于项目的 `data/`；通过 `DUALARB_DATA_DIR` 可选择其他目录。备份前停止程序，再复制整个数据目录。保留加密保险库、公开钱包元数据和交易档案之间的一致性。

服务只监听回环地址，并检查 Host、Origin、会话 Cookie 和修改请求的 CSRF。页面不需要远程登录，也没有远程访问开关。不要自行反向代理到公网，或把本机数据目录放入公开同步目录。

## 8. 本地验收

运行 `npm test`、`npm run check` 后，在默认演示模式完成下列检查：

- 两链卡片和报价自动刷新，页面明确显示演示。
- 跨链模式单次执行保存完整的买入、跨链、卖出与复核记录；库存模式保存买入确认后卖出现有库存的两笔记录及库存变化、精度余数。
- 利润、费用或次数限制不满足时，首页给出不执行原因。
- 备忘录保存后有时间，翻页正常，重启后仍在。
- 私钥导入响应和页面不包含私钥；重启后必须解锁，已保存地址仍可查看。
- 两条链插件连接分别显示账户；取消连接、账户切换和断线有明确反馈，重新加载页面需重连。演示模式不弹交易签名。
- 手动跨链显示到账和磨损；失败记录要求先人工核对再恢复自动运行。
- 新交易详情保存参数快照和指纹；本地复盘按模式与完成日期统计，缺失费用不冒充已复核收益，导出不含钱包、哈希或备忘录内容。

测试使用模拟器、受控假回执和模拟插件接口；没有在用户已安装的钱包插件或真实资金上完成验收，也不代表已经验证用户 RPC、OKX 权限与实际代币路线。

浏览器自动验收：开发依赖安装后运行 `npm run test:ui`。如未安装 Chromium，先运行 `npx playwright install chromium`，或用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定本机 Chromium 路径。验收只创建临时演示数据并会在结束后删除。

如果页面显示 `ERR_CONNECTION_REFUSED`，先核对地址栏端口与当前启动窗口一致，并确认浏览器和程序在同一台电脑。Windows 可在另一个命令窗口运行 `curl.exe --noproxy "*" -I http://127.0.0.1:实际端口/`：返回 HTTP 200 表示本机服务可以访问，再检查浏览器代理对本机地址的绕过设置；连接拒绝时检查程序是否仍运行。无需自动打开浏览器时用 `npm run start:server`。

## 9. 使用 Meme 观察雷达

打开“行情首页”→“Meme 雷达”。这是五标签布局内的行情子视图，自动扫描默认关闭，重启后仍关闭。先在 [AVE 官方 Cloud](https://cloud.ave.ai/register) 注册并申请自己的数据 API Key，在“AVE Key 与本地语音”中使用保险库密码加密保存；无需连接钱包、输入私钥或 OKX 凭据。重启后在“设置与钱包”解锁，回到雷达手动开启。保存 Key 不调用 AVE，成功保存不表示已验证账户权限；已有保险库若锁定，保存后仍保持锁定。

选择 BNB Chain 或 Solana 后点击“开启只读扫描”。每次最多读取所选链的 30 个榜单代币，界面每页 10 条；它不扫描全市场。即使套利处于演示模式，开启雷达也会请求真实 AVE 数据；没有 Key 时不生成假数据。默认阈值为流动性至少 20,000 USD、市值 50,000–10,000,000 USD、5 分钟成交额至少 5,000 USD、持币人数至少 100、币龄 30 分钟–168 小时，可在“筛选与请求预算”调整。

“市场观察”仅表示行情条件初筛通过，安全仍待核验。行情采集及来源时间超过固定 10 分钟、来源时间未知、所需数据缺失或有明确风险时查看“已筛除／资料不足”。手动“查询风险资料”读取独立合约报告；发现明确风险标志会隔离，报告未知或未检出标志都不会变成安全认证。榜单中已废弃的安全字段不作为判断依据，已发现的风险也不会被后续未知结果清除。同名代币不证明跨链同币，雷达不修改套利地址、池或触发交易。

所有行情、手动刷新和风险查询共用全局至少 5 分钟间隔。默认请求预算为滚动近 1 小时 12 次、滚动近 24 小时 144 次、累计 1,000 次；派发前保存计数，失败同样占用。重启、更换 Key、切换链不能清除预算或冷却；窗口不是按午夜重置。发生限流会退避，鉴权／套餐失败会停止扫描。此为本机请求次数控制，第三方 API 免费额度与收费以 AVE 为准。

可复制 CA、跳转固定 AVE 代币页，或收藏最多 100 个观察代币并保存每条最多 1,000 字的本地备注。语音默认关闭，须手动启用中文／英文的本地系统声音；不支持本地声音或 Web Locks 时页面会解释原因。首次加载及重新开启不补播旧记录，多个同源标签页协调去重。实际开始播报后才置顶高亮，减少动态效果设置会关闭闪烁。提醒只代表新的市场线索，不代表买入建议。

详细数据来源、限制、官方 v2 鉴权区别和参考仓库固定版本见 [MEME-RADAR.md](MEME-RADAR.md)。本地测试使用受控响应，没有使用真实 AVE 账户验证实时数据、计费或用户套餐权限。

## 10. 同币机会与双侧库存套利

打开“行情首页”→“同币机会”。可从 CoinGecko 多链目录发现候选，也可手工填写 BNB 合约和 Solana mint；随后按准确地址扫描 DexScreener 池。目录同一 ID 不保证资产等价，执行前还需核实两链 1:1 映射、decimals、交易池并填写依据。新候选默认没有交易资格，地址等参数改变后需重新核验，币名相同不作为同币证据。

扫描默认关闭，重启后关闭。每轮默认扫描 30 个清单项目，默认间隔 60 秒、最低流动性 20,000 USD、参考价差至少 0.5%；两侧参考池数据最多有效 120 秒，来源更新时间未知时如实显示。扫描结果的参考毛差价不含完整费用，不能当作可执行净利润。先对已核验项目获取当前 1–10U 双边报价，查看库存、费用、滑点、授权等检查结果，再执行单笔或明确开启已核验清单自动执行。扫描和核验本身不会开交易，也不会切换演示／实盘。

库存模式要求高价侧已有目标币、低价侧有稳定币、双方保留 Gas。先买入确认，再按实收数量卖出另一侧已有库存；买入的新币仍留在低价侧。连续同方向交易会消耗库存，库存不足跳过，不自动跨链补仓，也不触发自动稳定币再平衡。显示的现金流价差扣除了本轮费用和租金，但未来补库等成本未必在回执中；结合库存变化和余数阅读，不能视作库存已配平的闭环利润。

新扫描源共享持久请求预算：至少 1 秒间隔、每分钟最多 30 次、默认滚动 24 小时最多 5,000 次；目录缓存至少 6 小时。失败计数，限流退避，手动刷新和重启不能绕过预算。公开目录可能要求账户或不可用，此时可改用手工清单，不会生成假数据或换用未经核验的接口。API 免费额度和收费仍以提供方为准。

完整配置、成交与归档说明见 [INVENTORY-OPPORTUNITIES.md](INVENTORY-OPPORTUNITIES.md)。实盘仍受原 OKX 支持格式、配置池、精确 ERC20 授权、白名单和经典 SPL Token 限制；插件钱包每笔仍需人工确认。本轮开发未使用真实提供方账户或资金完成验收。
