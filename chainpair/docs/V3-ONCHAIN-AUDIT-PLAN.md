# V3.0 链上机会研究：审计与增量升级计划

审计日期：2026-11-24（Asia/Shanghai）。基线：ChainPair v1.9.0。用户最终选择继续在BNB Chain／Solana链上寻找同币机会，因此本次不新增中心化交易所账户和订单模块。

## 现有安全基础与保留功能

- `src/server.mjs`已有本机监听、Host／Origin、会话、CSRF、CSP及固定接口；Windows启动器、端口自动选择、五个管理标签保留。
- `src/vault.mjs`使用scrypt与AES-GCM本机加密。原OKX凭据用于Web3聚合，并不是中心化交易所账户或提现权限证明。本次不引入交易所提现或自动划转。
- `src/opportunities/service.mjs`已按明确CA／canonical资产来源、同轮价格、池活跃度、多池一致性和异常隔离筛选。币名相同仍不能证明同币。
- `src/engine.mjs`、`src/live-readiness.mjs`和`src/bnb-approval.mjs`已有实盘顺序确认、双边未签名模拟、有限授权、持久化提交意图、实际费用和到账核算、失败暂停与不重播。原实盘本金1–10U限制保留。

## 确定的缺口

1. 扫描主要保存最新行情。缺少价差持续时间、断档、重复出现次数、双向复发和历史真实报价净值；一次巨大参考差价不能视为可执行利润。
2. 现有真实报价检查只覆盖当前全局金额和参考价格选出的方向，无法形成1／2／5／10／20／50U双向报价矩阵。20／50U不应通过放宽原实盘限制实现。
3. 真实报价、未签名模拟和实盘回执是不同证据，当前只有少量内存最新报告，不能充当14天策略验证。
4. 原DEMO是固定行情和虚拟资金流程演练，不能用于证明链上套利盈利。新paper必须引用真实池和延迟后的真实兑换报价，不生成随机行情、成交哈希或收益。
5. 原`Engine.init()`会核对旧交易表所有未完成状态，原库存键限定BNB／Solana。研究／paper若写旧表，会污染实盘统计与重启恢复；新账本必须独立保存。
6. AMM池流动性不等于限价订单簿可成交深度。链上exact-in单笔通常原子成功或失败，不应虚构CEX式部分成交；两链买卖之间的单边敞口仍须记录和暂停。
7. 公共行情受来源覆盖、权限、限速和网络影响。不得通过旧缓存、同名匹配、密钥轮换或虚假新时间填充机会。

## 分模块实施

1. 独立研究存储与机会历史：只在成功的新扫描提交后记录，绑定资产版本、方向、策略版本和扫描批次。按真实相邻采样间隔计算持续段、覆盖与断档，重启停机不算持续验证。
2. 双向多档只读报价：逐个金额和方向构造准确输入→买入最低到账→另一链准确卖出报价，保存费用、租金、平均执行价、保守净值、压力值及不通过原因。缺身份确认保持候选，不授予交易资格；缺精度须链上读取，不能猜测。
3. 独立paper状态机与账本：虚拟初始资金明确标记，按真实新报价考虑延迟和费用；保存现金、目标币、预占、单边敞口、费用、模拟收支、净值和回撤。亏损再平衡不自动执行，不跨链划转，不调用签名或广播。
4. 原网页新增链上研究视图：排行区分参考价差、真实报价和paper结果；显示覆盖、双向出现、过期／身份／库存原因。所有实盘动作继续通过原预检与人工启用，不由paper或排名触发。
5. 自动化验收：覆盖身份错误、旧行情／断档、重复记录、限速、数量精度、深度／报价不足、延迟变价、单边失败、库存耗尽和重启。保留原测试与浏览器流程。

## 验收边界

默认研究／paper不发送真实交易。开发过程不使用真实账户私密API、不读取用户私钥、不下载未知脚本、不装全局依赖或更改系统权限。实际运行14天之前，只交付记录器与当前真实进度；不预填历史、不宣称已达标、盈利或未来七成成功率。当前Solana路由最小到账指令尚未独立解码、美元参考估值和未来补库成本等已知边界继续明示。
