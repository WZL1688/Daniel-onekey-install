# AI 接手规则

开始修改前，依次阅读本文件、`docs/PROJECT_MEMORY.md`、`docs/PROGRESS.md`、`docs/MAINTENANCE_LOG.md`。涉及交易时再读 `docs/ARCHITECTURE.md` 与 `docs/VERIFICATION.md`，并检查当前源码；文档中的计划不能当作已完成事实。

## 不变条件

- 这是本地浏览器工具。保持开发服务器仅监听 `127.0.0.1`；用户未授权时不发布、不部署、不替用户执行交易。
- 已授权支持两个独立配置：HyperEVM `999` / Uniswap v3，以及 Elysium `99901` / Uniswap v4。钱包、RPC、授权目标、交易编码和采样记录必须按配置隔离。不得把其他 DEX 的兼容池标为官方部署；v4 合约身份未通过校验时禁止签名。
- 余额、持仓、手续费来自链上。缺失、过期、RPC 失败必须明确显示，不得生成示例持仓、替补行情、虚构 APR。
- 预算、滑点、价格范围、接收地址和期限必须在交易预览中确定。修改输入即使原预览失效。
- 每一步签名前重新核对账户和链，执行 `eth_call` 与 gas 估算。失败立即停止，不自动放宽滑点、不自动重发、不隐式继续失效计划。
- ERC20 仅按所需金额授权；必要时先清零。v3 原生 HYPE 包装为 WHYPE，v4 原生 HYPE 直接结算，不得混用。v4 Permit2 精确额度和到期不超过计划期限；两条链的 Gas 预算和原子撤仓均须明确。
- v4 领费 DECREASE(0) 的本金 minimum 为零，不是费用最低到账承诺；不可把费用写入本金 minimum 后通过自动放宽滑点解决。四个合约的完整官方部署 runtime 指纹与管理器关联未通过时禁止签名；泛化 npm mask 匹配不能作为替代放行条件。地址来源、代码匹配与实际链上状态分别记录。
- v4 广播结果未知时保留哈希/nonce 和按账户的 pending 锁。执行与恢复共用跨标签页原子锁。只读核对真实交易及确定回执后恢复；取消/替换须手动哈希、同账户同 nonce 和已确认 nonce 推进，仅允许重做预览。不提供绕过复选框、自动过期解锁或清站点数据建议。
- 钱包私钥、助记词、签名秘密不能进入代码、日志、导出文件或聊天。连接钱包不是交易授权。
- 年化和秒级收益是有限历史样本的估算，不能称为保证收益；真实待领数量与估算必须区分。

## 维护流程

先检查工作区差异，保留其他协作者的修改。改动后运行适当的类型检查、单元测试及构建；涉及钱包或交易时补充人工/受控钱包验证结果，不能以 mock 测试冒充主网验证。

每次交接更新：

1. `PROJECT_MEMORY.md`：已确认的长期决策与新增约束。
2. `PROGRESS.md`：当前实现状态、阻塞、下一步。
3. `MAINTENANCE_LOG.md`：追加日期、原因、改动、验证与剩余风险。
4. `VERIFICATION.md`：记录实际执行的命令、结果和未覆盖部分。

仓库文档负责跨 AI 记忆；后续 AI 必须读取这些文件才会获得上下文。不要声称不同聊天或不同产品会自动共享记忆。用户的明确指示优先于本文件。
